## 1. 현재 상태

### 1.1 배포 베이스 모델 (확정)
- **모델: yolo11s, 데이터 증강 없음 (채널 수만 증가)**
- val 500씬 held-out, imgsz=1280, 200 epoch 기준
  - mAP50 = 0.841, mAP50-95 = 0.685
  - P/R = 0.896 / 0.783
  - **나쁜 클래스(성능 하락) 0/34** — 34개 클래스 전부 baseline 대비 무손실 개선
- 가중치 경로: `mec_sim_ice/test/runs/detect/train_B/weights/best.pt`
- **이 모델(B)은 이후 작업에서 절대 직접 수정하지 않는다.** (이유는 3장 참고)

### 1.2 실패한 시도들 (참고용, 재시도 금지 또는 조건부 재시도)
| 시도 | 내용 | 결과 |

### 1.3 문제가 되는 소형 객체 클래스 (실측 데이터)
GT copy-paste로 추가한 인스턴스 기준, bbox 변 길이(px):

| 클래스 | 평균 | 중앙 | 최대 |
|---|---|---|---|
| disposable_cup | 6.6 | 6.0 | 21.0 |
| sunblock | 7.8 | 7.0 | 26.0 |
| tissue | 5.7 | 5.0 | 16.5 |

- 40px 넘는 인스턴스 0개. COCO "small" 기준(<32×32px)보다도 훨씬 작은, 사실상 tiny-object 영역(AI-TOD 데이터셋 평균 약 12.8px보다도 작음).
- imgsz=1280은 이미 최대 해상도 (해상도 추가 상향 불가).
- YOLO11 n/s/m/l/x 전부 stride [8, 16, 32] 동일. stride 8(가장 세밀한 feature map)에서 격자 한 칸이 8×8px인데, 이 세 클래스 평균 크기(5~13px)가 그 한 칸과 비슷하거나 작음 → 객체가 격자 1칸 안에 들어가는 수준이라 IoU 기반 매칭/loss가 극도로 불안정해짐.

## 2. 해야 할 작업

### 2.1 소형 객체 전용 별도 모델 학습
- 대상 클래스: disposable_cup, sunblock, tissue (3개, 필요시 유사 스케일 클래스 추가)
- **B 모델과 완전히 분리된 별도 모델**로 학습 — B의 34클래스 공유 백본/헤드는 건드리지 않음
- Loss / 라벨 할당을 IoU(CIoU) 기반에서 **NWD(Normalized Wasserstein Distance)** 기반으로 교체 또는 블렌딩
  - 대상 코드: Ultralytics `ultralytics/utils/loss.py`(BboxLoss)의 CIoU 계산부, `ultralytics/utils/tal.py`(TaskAlignedAssigner)의 IoU 기반 alignment metric
  - NWD의 정규화 상수 C는 논문 기본값(12.8, AI-TOD 평균 크기 기준)을 그대로 쓰지 말고, **이 프로젝트 실측 평균 크기(약 6~8px)에 맞춰 재튜닝**
  - 박스 크기에 따라 CIoU와 NWD를 가중 평균하는 스케일 적응형 블렌딩 고려 (다른 스케일 클래스로 오염 방지)

### 2.2 학습/추론 방식
- 학습 데이터는 **원본 이미지 그대로** 사용 (GT 크롭 학습 방식은 이미 성능 저하 확인됨 — 재시도하지 않음)
- 타일링은 **추론 시점에만** 적용 (SAHI 방식: 이미지를 겹치는 타일로 슬라이싱 → 각 타일 추론 → 원본 좌표로 병합)
- 학습 자체는 일반적인 방식대로 진행하고, 소형 객체 상대 크기 확보는 추론 슬라이싱으로 해결

### 2.3 두 모델 결과 병합
- 단순 concat/NMS가 아니라 **Weighted Boxes Fusion(WBF)** 사용
- 좌표계 정합: 소형 모델이 타일 단위로 돈다면 타일 local 좌표 → 원본 이미지 global 좌표 변환 필수
- **크기 게이팅**: 소형 모델의 예측 중 일정 크기 이하만 채택, 큰 객체 조각을 잘못 잡은 노이즈는 필터링
- confidence 스케일이 두 모델 간 다를 수 있으므로 threshold/calibration 별도 확인

### 2.4 검증
- 오프라인 mAP뿐 아니라, **실제 배포 파이프라인의 conf=0.35 컷을 그대로 적용한 후**의 소형 클래스 recall/최종 산출 결과 기준으로 개선 여부 확인
- WBF 병합 시 confidence가 평균/가중합 과정에서 threshold 밑으로 떨어지는 경우가 없는지 점검
- 병합 후 나머지 31개 클래스(소형 모델과 무관한 클래스)에 성능 저하가 없는지 반드시 재확인 (B 결과가 그대로 보존되는지)

## 3. 주의사항 (반복적으로 확인된 실패 패턴)

1. **공유 모델(B)에 직접 손대는 모든 시도는 지금까지 전부 실패했음.** 오버샘플링, GT copy-paste, P2 head 추가 — 방식은 다 달랐지만 공통적으로 "특정 클래스 개선 시도가 다른 클래스로 여파를 주는" 트레이드오프가 발생함 (recall↑ precision↓ 상쇄, 또는 9~21/34 클래스 하락). 이번 작업은 이 실패 패턴을 반복하지 않도록 **B와 완전히 분리된 모델 + 후처리 병합** 구조를 반드시 유지할 것.
2. NWD의 정규화 상수는 반드시 이 프로젝트 실측 크기(6~8px)로 재설정. 논문 기본값 그대로 쓰면 효과가 없거나 역효과 가능.
3. 병합 단계에서 confidence 왜곡으로 인해 실제 채점 threshold(conf=0.35)를 못 넘기면, mAP가 올라도 실채점 점수는 안 오를 수 있음 — 반드시 threshold 적용 후 결과로 검증.
4. imgsz는 이미 1280이 최대치이므로 해상도를 더 올리는 방향은 옵션에서 제외.
5. 행동/문맥 기반 클래스(예: "쓰레기를 버리는 사람" 등)는 이번 소형 객체 문제와 별개 사안임 — 단일 프레임 person crop만으로는 원리적으로 구분이 어려운 클래스라, detection 아키텍처 개선으로는 한계가 있고 별도로 관계/문맥 정보(주변 객체와의 상대 위치, 프레임 간 상태 변화) 기반 접근이 필요함. 이번 작업 범위에서는 다루지 않음.
