## 1. `json.txt` 코드 검사

`detections[].class` 스키마를 참고해 `demo/real_agent_vla.py`(클래스 정의), `demo/train_yolo11.py`
(라벨 변환)와 대조 검토.

- `json.txt` 자체가 문법적으로 깨진 JSON이었음 (`ground_height` 숫자 중간에 로컬 파일 경로 문자열이
  끼어 있어 `json.loads` 실패). 파일 옮기는 과정에서 깨진 것으로 확인 — 실제 dataset-gen 산출물
  문제는 아님.
- 스키마만 놓고 보면 `detections[].class` 실제 값이 `real_agent_vla.py`의 클래스 목록과
  다수 불일치 (아래 2번 참고).

## 2. 클래스 이름 불일치 수정

`real_agent_vla.py`의 `TARGET_CLASSES`/`LANDMARK_CLASSES`는 `problems.yaml` 문항 id에서 추론한
것이라 실측 미검증 상태였음. `marc2026_demo` 씬으로 실측 확인한 값과 코드를 맞춤.

**[demo/real_agent_vla.py](real_agent_vla.py) — `LANDMARK_CLASSES`**
```python
# 이전
LANDMARK_CLASSES = ["table", "bench", "hydrant", "vending", "fallenbike",
                     "parking", "taxi", "bikerack", "park", "trash"]
# 이후
LANDMARK_CLASSES = ["picnic_table", "bench", "hydrant", "vending_machine", "fallenbike",
                     "parking", "taxi", "bikerack", "park", "trash_can"]
```
(`table`→`picnic_table`, `vending`→`vending_machine`, `trash`→`trash_can`)

**[demo/train_yolo11.py](train_yolo11.py) — `_to_yolo_line`**: 사람은 `person` 단일 클래스가 아니라
`person_walking`/`person_crouching`/`person_prone`/`person_lying_down` 등 자세별 세부 클래스로
찍힘. 학습용 `person` 하나로 묶는 매핑 추가.
```python
if cls and cls.startswith("person_"):
    cls = "person"
```

`hydrant`/`fallenbike`/`parking`/`bikerack`/`park`은 이번 샘플에 없어서 검증 못 함 — 그대로 둠.

> **(후속 변경, 8번 참고)** 여기서 넣은 `person_*` → `person` 매핑은 이후 8번 작업에서 되돌림 —
> situation을 4종까지 구분하려면 세부 자세 클래스를 살려두는 게 맞는다고 판단.

## 3. `simulation-platform/.env` 생성

`.env.example`을 복사해 `simulation-platform/.env` 생성 (gitignore됨, 로컬 전용).
`TRAINER_AUTO_SCENES=100` 추가:

## 4. dataset-gen 산출물 구조 확인

`train_yolo11.py convert`의 `--scenes` 폴더는 2단계 구조 고정:
```
--scenes 폴더/
├── scene_00000/
│   ├── rig_3_c.json
│   └── rig_3_c.png
├── scene_00001/
│   ...
```
`scene_*` 하위 폴더 이름에 zero-padding 있어도 무방 (`scene_` 접두사만 맞으면 됨). 더 깊은
하위 폴더는 인식 못 함 (재귀 탐색 아님).

## 5. `convert` 0/0 버그 수정

`marc2026_demo` 씬 132개로 `convert` 실행 시 `wrote 0 train / 0 val images` 발생.

**원인**: 실제 JSON 스키마는 이미지 해상도가 `payload["image"]["width"/"height"]`에 있는데,
코드는 `payload["camera"]["width"/"height"]`(또는 `camera.intrinsic`)만 확인해서 항상 못 찾고
전체 씬이 스킵됨.

**[demo/train_yolo11.py](train_yolo11.py) 수정**:
```python
# 이전
cam = payload.get("camera", {})
img_w = cam.get("width") or cam.get("intrinsic", {}).get("width")
img_h = cam.get("height") or cam.get("intrinsic", {}).get("height")
# 이후
img_info = payload.get("image", {})
cam = payload.get("camera", {})
img_w = img_info.get("width") or cam.get("width") or cam.get("intrinsic", {}).get("width")
img_h = img_info.get("height") or cam.get("height") or cam.get("intrinsic", {}).get("height")
```

수정 후 재실행 결과: **181 train / 20 val images**, 라벨 총 2578줄 (`wc -l dataset/labels/train/*.txt`)
— 정상적으로 박스가 채워짐 확인.

## 6. 학습 단계 (`train_yolo11.py train`)

- `--imgsz 1280`은 임의값이 아니라 CCTV 원본 해상도(1280×720)에 맞춘 것. 학습/추론
  (`real_agent_vla.py`의 `DET_IMGSZ`) 둘 다 같은 값 유지해야 함.
- 학습 중 `ConnectionResetError: [Errno 104] Connection reset by peer`
  (dataloader/`pin_memory` 스택트레이스) 발생 — 데이터로더 워커가 OOM으로 커널에 의해
  강제종료된 것으로 추정.
- **[demo/train_yolo11.py](train_yolo11.py)에 `--batch`/`--workers` CLI 옵션 추가**
  (기본값은 ultralytics 기본값인 16/8과 동일, 안 주면 기존과 동일 동작):
  ```bash
  python3 train_yolo11.py train --data dataset/data.yaml --epochs 100 --imgsz 1280 \
    --batch 4 --workers 2
  ```
  `dmesg | tail -30`에 `Out of memory: Killed process`가 있으면 OOM 확정.

## 8. situation(자세) 4종 분류 재설계 + 만점 검증 기반 마련

학습까지 마친 뒤 `problems.yaml.example`의 `sar*`/`sarH*` 문항(사람 자세 기반 SAR 문제)을 검토하다가,
기존 `_classify_situation`(범용 COCO pose 모델 + 어깨/엉덩이/발목 keypoint 휴리스틱)이 구조적으로
`normal`/`abnormal` 두 갈래만 반환할 수 있고, 공식 문서(`MARC2026_요약_v2.md`)가 명시한 4종
(`accident`/`emergency`/`abnormal`/`normal`) 중 `accident`/`emergency`는 **절대** 만들어낼 수 없다는
걸 발견 (코드 자체 주석도 이미 인정하던 부분). Explore agent로 `marc_sdk`/`participant_app.py`/
`MARC2026_요약_v2.md`를 조사해서 situation 4종·relation 8종 공식 어휘, `GroundingResult` 필드,
`Score.scores`가 라운드별로는 `.total`만 로그되고 있었다는 것도 확인함 (plan mode로 설계 후 승인받아 진행).

**변경 요지**: dataset-gen이 이미 사람 자세를 `person_walking`/`person_crouching`/`person_prone`/
`person_walking_away`/`person_reclining`/`person_bending`/`person_lying_down` 7개 클래스로 정확히
라벨링해서 내려주고 있으므로, 별도 pose 모델 대신 **파인튜닝하는 detection 모델이 이 7개를 직접
구분**하게 하고, 그 클래스를 situation 4종에 매핑하는 방식으로 교체.

- **[demo/train_yolo11.py](train_yolo11.py)**: 2번에서 넣었던 `person_*`→`person` 매핑 제거 (7개
  클래스 그대로 유지).
- **[demo/real_agent_vla.py](real_agent_vla.py)**:
  - `DET_CLASSES`에 `["person"]` 대신 `POSE_CLASSES`(7개) 포함
  - `POSE_TO_SITUATION`(자세→situation 매핑, 심각도순 best-effort), `POSE_SEVERITY`(심각도 순서) 추가
  - `_pose_model`/`POSE_WEIGHTS`/`_classify_situation`/`_situation_from_keypoints`/
    `KP_SHOULDER`/`KP_HIP`/`KP_ANKLE` 전부 삭제 — 별도 pose 모델 자체가 불필요해짐
  - `_best_box`를 대체하는 `_best_person_box(det, situation)` 신설: 요청된 situation과 매칭되는
    자세 클래스 중 최고 confidence 박스 반환, 없으면 가장 심각한 자세로 fallback
- **[demo/Dockerfile](Dockerfile)**: `yolo11n-pose.pt` 빌드타임 다운로드 단계 제거 (더는 안 씀)
- **[demo/participant_app.py](participant_app.py)** `_on_score`: 라운드별로도 `.total`이 아니라
  `score.scores` 전체를 로그하도록 변경 — 실제 채점 breakdown이 있는지, `POSE_TO_SITUATION`의
  accident/emergency 추정이 맞는지 검증할 실측 데이터를 확보하기 위함
- 가이드 md의 0/1-1/5-3/5-5 섹션도 이 변경에 맞게 갱신

**중요한 한계**: `TARGET_CLASSES`/`LANDMARK_CLASSES`/`RELATION_WORDS`/`SITUATION_WORDS`가 한국어
`voice_command` 실측 문장 없이 추측으로 짜여있다는 문제(모듈 docstring이 이미 인정)는 이번에도
해결 못 함 — 플랫폼을 한 번 돌려서 실제 `voice_command`/`score.scores` 로그를 잡아야만(위 참고)
검증 가능. 채점 가중치·임계값 자체도 대회 문서가 "공식적으로 비공개"라고 명시하고 있어서,
정적 코드 수정만으로 "만점"을 보장할 수는 없음 — 이번 작업은 확인된 구체적 결함(situation 이분법)을
고치고 다음 보정에 필요한 로그 기반을 마련한 것까지.
