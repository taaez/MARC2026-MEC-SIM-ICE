### 2-4. 이동 직후 실제로 깨졌던 것 — 발견하고 고침

폴더만 옮기면 끝나는 게 아니라, 데이터셋 안에 **절대경로가 박혀있는 파일들**이 있어서 실제로
깨졌었음. 사용자가 "코드 돌리는 데 문제없이 한 거 맞냐"고 재차 확인해서 찾아냄:

1. **`data.yaml`의 `path:` 필드가 절대경로**로 옛 위치(`mec_sim_ice/test/dataset_v2` 등)를
   가리키고 있어서, 이동 후 그대로 두면 학습/변환 시 이미지를 못 찾아 에러 남. 4개 데이터셋
   (`dataset_v2`, `dataset_v3_oversample`, `dataset_v4_gtsample`, `dataset_small_t640`)
   전부 새 절대경로(`mec_sim_ice/datasets/<이름>`)로 수정함.
2. **오버샘플/GT샘플 데이터셋의 심볼릭 링크 3,688개 전부**(`dataset_v3_oversample`,
   `dataset_v4_gtsample`의 train 이미지/라벨 심링크)가 옛 절대경로를 가리키고 있어서 **전부
   깨져있었음**. 전량 스크립트로 재연결(`mec_sim_ice/test/` → `mec_sim_ice/datasets/`
   접두어 치환) — 재확인 결과 깨진 링크 0개.
3. `dataset_small_t640/tiling.json`의 `source` 필드(옛 절대경로)도 같이 고침 — 이건 코드에서
   실제로 안 읽는 정보성 필드라 안 고쳐도 동작엔 문제없었지만 기록 정확성을 위해 맞춰둠.
4. `training/small_object_detection/소형객체_서브모델_가이드.md`, `training/YOLO11_학습_가이드.md`,
   `training/README.md` 안의 예시 명령어(상대경로)도 새 폴더 배치에 맞게 고침.

**이동 후 실제로 검증한 것** (전부 통과):
- `train_yolo11.py`/`small_object_detection/*.py`에서 `det_classes` import 정상
- `dataset_v2` data.yaml 기준 train 601장 / val 500장 정상 인식
- `dataset_v3_oversample`(train 2188장), `dataset_v4_gtsample`(train 601장), `dataset_small_t640`
  (train 3027장) 전부 깨진 심링크 0개로 정상 인식

**로그 저장 위치도 고침 (2026-08-29 추가 수정)**: `train_yolo11.py`/`train_small.py`는
로그 저장 폴더(`logs/`)를 **cwd가 아니라 스크립트 자기 파일 위치 기준**으로 계산했음
(`os.path.dirname(os.path.abspath(__file__))/logs`). 그대로 두면 다음 학습부터 로그가
`training_results/`가 아니라 `mec_sim_ice/training/logs/`에 새로 생겨서 다시 흩어지는
문제가 있어, **두 스크립트 다 `mec_sim_ice/training_results/yolo_main_logs/`를 가리키도록
코드 수정함** ([train_yolo11.py:380](../training/train_yolo11.py#L380),
[small_object_detection/train_small.py:75](../training/small_object_detection/train_small.py#L75)).
이동 전 로그가 이미 그 폴더에 있었으니 앞으로도 계속 한 곳에 쌓임 — 재확인해서 두 스크립트가
계산하는 경로가 정확히 같은 폴더로 일치하는 것 확인함.

> 참고로 학습 **결과(가중치 등, `--project`)**는 안 건드림 — Ultralytics 기본값이 원래도
> "cwd 기준 `runs/detect`"라 인자 기반으로 이미 명시적으로 관리되는 부분(팀 컨벤션: 항상
> `--project`/`--name` 직접 지정, `SESSION_REPORT_2026-08-27.md` 참고)이라 로그처럼 조용히
> 흩어지는 문제가 없음.

## 7. 사고 기록 ② — 로컬이 원격보다 27커밋 뒤처져 있던 것 발견, pull로 해결

정리 작업 다 끝난 뒤 taejeong 파이프라인(`demo/participant_app.py`, B 가중치)으로 충무 문제를
돌렸는데 점수가 낮게 나옴(Stage1 평균 51.42, 33라운드 중 12라운드 `camera` 오선택, 4라운드는
완전 실패). 사용자가 "원래 60대 후반 나왔는데?"라고 지적해서 확인해보니:

- **로컬 `ptj/stage1-vla-integration`이 `origin/ptj/stage1-vla-integration`보다 27커밋 뒤처져
  있었음.** 마지막으로 받은 게 909a3ca(리포 정리 커밋)였고, 그 뒤로 카메라 선택 로직 개선
  (`ae3f187: 카메라 선택을 순위매기기에서 제약충족으로 재설계` 등), DINO/VLM 폴백 추가,
  좌표 z 규약 통일 등 커밋 메시지에 점수 추이(40.27 → 53.03 → 57.80 → 61.71 → 64.25 →
  65.51 → 65.78)가 그대로 적혀있는 일련의 수정이 원격에만 쌓여 있었음
- **이번 정리 작업과는 무관** — 애초에 정리 시작 전부터 이미 27커밋 뒤처진 상태였음(확인:
  `demo_agents/weights/best.pt`는 정리 작업 훨씬 전부터 비어있었고, 정리 과정에서
  `mec_sim_ice/test/` 관련 파일을 지우거나 옮긴 게 원인도 아님 — `git log 909a3ca..9de852d --
  mec_sim_ice/test/`로 확인해보니 그 27커밋 중 `mec_sim_ice/test/`를 건드린 커밋은 0개)

### 처리 순서 (git 작업, **push 없음** — pull만)

1. `git stash push -u`로 오늘 정리 작업(추적 변경 + untracked 신규 파일 전부) 대피
2. `git pull origin ptj/stage1-vla-integration` — 27커밋 fast-forward, HEAD가 `9de852d`로
   원격과 완전히 일치하게 됨
3. `git stash pop` — 충돌 1건 발생: `mec_sim_ice/OFFLINE_검증_가이드.md`
   (정리 작업에서 `docs/`로 옮겼는데, 마침 이 파일도 pull된 커밋에서 내용이 갱신돼 있었음).
   **pull된 최신 버전을 `docs/`로 옮기는 걸로 해결**(예전 stash 버전 대신 최신 내용 채택).
   나머지는 전부 자동으로 깔끔하게 재적용됨
4. 재확인: `datasets/`의 심링크 3,688개 여전히 정상(0개 깨짐), `mec_sim_ice/docs/` 17개
   파일 전부 그대로, `mec_sim_ice/taejeong/`에 새로 받은 `dino_fallback.py`/`fallback.py`/
   `stage2_geometry.py`/`vlm_fallback.py` 확인
5. 내가 만든 stash(`stash@{0}`)만 `git stash drop`으로 정리 — 이전 세션이 남겨둔 다른
   stash 2개(`rebase 전 임시 보관`, `pull 전 로컬 수정 보관`)는 손 안 댐

**결과**: 로컬이 원격과 완전히 동기화됐고(HEAD `9de852d`), 오늘 정리한 폴더 구조도 그 위에
그대로 살아있음. 이제 다시 실행하면 카메라 선택 로직이 고쳐진 버전이라 60대 점수가 재현될
것으로 예상 — 재검증은 다음 실행에서 확인 예정.
