## 1. 비교 구성

| | **Baseline (legacy)** | **Proposed (mppi)** |
|---|---|---|
| 전역 경로 | 점유지도 A* (도로 밖 = 막힘, 로봇 반경 침식) | 지역 내비게이션 함수 V(x, y): 목표에서 거꾸로 돌린 Dijkstra cost-to-go (도로 밖 lethal, 장애물 근접 비용) |
| 경로 추종 / 제어 | PathFollower + GoalSeek **P 제어** (헤딩 오차 비례 각속도, 거리 비례 선속도) | **MPPI** (K=1024 샘플 × 2.5 s, 차체 제약을 굴리는 중 강제, 끝점 비용 = V) |
| 장애물 회피 | 라이다 칸이 경로를 막으면 **원호 우회**(waypoint_avoid.relocate: 막힌 구간만 원 둘레로 휨), 실패 시 A* 재계획, 실패 시 직선 폴백 | V 에 이미 우회 방향이 들어 있음 + 도달 불가 시 단계적 완화(로봇 반경 축소 → 오래된 라이다 칸 제외 → 가까운 칸만 → 도로 밖 허용), 단계 15 s 유지 |
| 정체 복구 | 8 s 정체 판정 → 정체 기억 원판 + 연속 시 후진 | 동일 + **pinned**(1.5 s 전진 명령에 무이동 → 즉시 후진), 전 롤아웃 충돌 시 정지 |
| 연석·단차 | (지도 경계 = 막힘) | 지도 경계 + **단차 레이어 충돌 판정**(라이다/depth 지면 높이 계단, 선 모양만, 롤아웃에서만 사용) |

**공통(두 구성 동일)**: 라이다 장애물 레이어 + depth ghost-veto, 반응형 브레이크, leg1 "물체로 가다가 0.58 m 에서 정지",
정렬·직진 접근·파지(placo DLS)·긴 물체 운반, 픽 시퀀스 60 s 상한, 배송 판정. 즉 **주행 플래너만** 다르다.
스위치: 환경변수 `MARC_LOCAL_PLANNER=legacy|mppi`.

## 5. 해석

1. **완주율과 재현성이 가장 큰 차이**: mppi 10/10, legacy 5/10. legacy 는 1차에 성공한 rt01·rt02·rt04 가 같은 코드의 2차에서
   모두 배송 단계에서 실패했다. 실패는 매번 "장애물 밀집 구간 또는 도로 경계에서 A* 실패 → 직선 폴백 → 정체 / 도로 밖 진입"
   이었다. 라이다 장애물 칸이 런마다 조금씩 다르게 쌓이면 A* 가 경로를 못 찾는 순간이 생기고, 그때 대안이 직선 폴백뿐이다.
   mppi 는 같은 상황에서 도달 불가 단계 완화(반경 축소 → 오래된 칸 제외 → 가까운 칸만 → 도로 밖 허용)로 항상 길을 다시 열었다.
2. **주행 효율**: 둘 다 완주한 5쌍에서 주행 시간 −24 %, 평균 속도 +26 %, 거리는 비슷(−4 %). 시간 단축은 경로가 짧아서가 아니라
   **멈춤이 적어서**다(브레이크 −81 %, 정체 −85 %). legacy 는 장애물 근처에서 "브레이크 → 정체 → 원호 우회/재계획"을 반복한다.
3. **장애물 밀집 구간(rt04b)**: legacy 는 2회 모두 물체에 닿지 못했고(1차 6.4 m 앞 A* 281회, 2차 0.72 m 앞 끼임) mppi 는 2회 모두
   픽까지 성공했다. V 에 우회 방향이 들어 있고, 도달 불가 시 반경을 0.30 → 0.22 m 로 줄여 좁은 틈을 다시 연다.
4. **자세 안정성**: legacy 는 1차 rt01 에서 턱 고속 통과(roll 40.6°), 2차 rt02 에서 도로 밖 진입 후 **전복**. mppi 는 횡가속 제한과
   도로 밖 lethal 로 대부분 4–16° 였지만, 2차 rt04 에서 꺼지는 단차 + tilt guard 후진으로 roll 61.5° 순간이 한 번 있었다.
5. **rt03 감점은 주행이 아니라 파지**: 두 구성이 같은 자리(9 cm 차)에 서도 도착 헤딩에 따라 누운 우산의 파지점이 달라졌고
   (legacy 전방 0.38 m, mppi 0.70 m) mppi 는 2회 모두 실패했다. 플래너 비교에서는 분리해 읽고, 도착 헤딩·재측정으로 따로 다룬다.
6. **점수와 시간**: 이 문항들은 성공 여부로 점수가 갈리므로 점수 차(평균 48.1 → 84.5)는 거의 전부 **실패 회피**에서 나온다.

## 6. 한계

- 문제당 2회라 런 간 편차가 크다(같은 코드 rt01 mppi 가 45점/95점이었던 적이 있다). 평균보다 경향과 실패 양상으로 읽을 것.
- 1차 mppi 런은 개발 중이라 문제마다 코드 버전이 조금 다르다(§3). 2차는 모든 런이 같은 코드다.
- mppi 의 단차 안전성은 완전하지 않다: 단차 충돌 판정이 2차 rt04 의 꺼지는 단차를 미리 막지 못했다(관측 3프레임 전에
  1.3 m/s 로 도달했거나 선 모양 필터에서 빠진 것으로 추정, 미확인). tilt guard 의 "기울어진 채 즉시 후진"도 롤을 키웠을 수 있다.
- 감시기 정리(0점 처리)는 실제 대회에서는 시간 초과까지 계속 시도하는 것과 다를 수 있다. 정리 기준(3분간 진전 없음,
  복구 동작 시 3회 유예)은 두 구성에 동일하게 적용했다.
- grounding 점수(Stage 1·2 VLA)는 두 구성에 같이 들어가므로 Stage2 점수 차는 픽·배송에서만 생긴다.
- 연습 플랫폼(GUI, RTF ≈ 0.18) 기준. 채점 서버 환경의 RTF 는 다를 수 있다.

### 7.4 3차 해석
1. **파지 재접근의 효과**: mppi rt03 픽+배송이 30 → 80 (1·2차와 3차 수정 전 모두 30). 같은 자리에 서도 도착 헤딩에 따라 누운 우산의 파지점이
   팔 도달 한계에 걸리던 문제를, 파지점 쪽으로 회전·전진해 legacy 와 같은 파지 거리(≈ 0.4 m)로 되돌렸다. 단 첫 재측정은 아직 불안정해
   성공은 2차 시도에서 나왔다.
2. **tilt guard 개선의 효과**: 발동 2회 모두 반복 없음, 30° 초과 0건(2차는 mppi 61.5°, legacy 전복 80.8°). 2차 rt04 의 롤은 단차에서
   떨어지는 움직임(odom −1.5 m/s)에서 생긴 것이라 tilt guard 개선만으로 막는다고 단정할 수는 없다 — 3차에서는 그 단차를 다시 만나지 않았다.
3. **주행 시간은 3차에서 역전**: 둘 다 완주한 4쌍에서 mppi 가 11.7 % 느렸다. 차이의 대부분이 rt04b(146.3 vs 90.0 s)와 rt04 leg1 이다.
   mppi 의 rt04·rt04b leg1 은 1차(단차 충돌 판정 도입 전) 48–56 s → 2·3차 76–141 s 로 늘었다. 2차부터 들어간 단차 충돌 판정과
   최후 수단 단계 속도 제한(0.6 m/s)이 장애물 밀집 구간에서 mppi 를 느리게 만든 것으로 추정한다(미분리 — 별도 ablation 필요).
4. **완주율 차이는 3차에도 유지**: legacy 는 rt02 에서 다시 배송 실패(원호 우회·직선 폴백으로 반대 방향 주행). mppi 는 3회 모두 15/15.

## 9. 파지 지표 (1·2·3차, 에이전트 로그 기준)

파지 단계(정렬 → 직진 접근 → depth 파지점 → placo 파지·운반)는 두 구성이 **같은 코드**다. 차이는 플래너가 만든
**도착 위치·헤딩**과 런 간 편차에서 생긴다. "성공" = 그리퍼가 잡고 있고 바구니에 들어감(`pick attempt N ok`).
물체에 도달하지 못한 런(legacy rt04b 1·2차)은 분모에서 뺐다.

| 항목 | legacy | mppi |
|---|---|---|
| **① 파지 성공률** (물체에 도달한 런 기준) | 9 / 13 (69 %) | **12 / 15 (80 %)** |
| └ 첫 시도 성공 | 8 / 13 (62 %) | **10 / 15 (67 %)** |
| **② 파지 시도·시간** — 총 시도 / 성공까지 평균 시도 / 평균 파지 시간 | 22 / 1.11 / **30.9 s** | 23 / 1.17 / 33.5 s |
| **③ 실패한 시도의 유형** (빈손으로 들어 올림 / 운반 중 낙하 / 팔 도달 한계 초과) | 13 (6 / 7 / 0) | 11 (3 / 8 / 2) |

- 물체에 닿는 비율 자체가 다르다: legacy 13/15, mppi 15/15 — 파지 성공의 첫 조건이 주행에서 갈린다.
- **mppi 의 실패 2건(팔 도달 한계)은 모두 rt03 누운 우산**: 도착 헤딩에 따라 파지점이 0.70–0.72 m 로 잡혔다. 3차의 **파지 재접근**
  (파지점 쪽으로 회전 → 0.47 m 까지 전진 → 재측정)으로 rt03 mppi 가 처음 성공했다(§7).
- **운반 중 낙하가 두 구성 모두 가장 많은 실패 유형**이다. 대부분 rt04 텀블러로, 씬에 약 25° 기울어져 놓여 있어 보는 방향에 따라
  "서 있음/누움" 판정과 손목 회전각이 달라지고, over/place 단계에서 손가락이 35–45° 로 벌어지며 놓쳤다(3차 rt04: 두 구성 4런 연속).
- 3차 이후 추가(아직 라이브 평가 전): **재시도 위치 재탐색**(현재 화면 → −30° → +30° 에서 마지막 위치 기준 0.6 m 창으로 depth 재측정,
  못 찾으면 남은 시도 생략 후 배송 — 첫 시도 실패·운반 중 낙하 모두 처리)과 **텀블러 운반 저속·고높이**(운반 높이 0.24 → 0.36 m,
  속도 0.40 → 0.25). 두 구성 공통이라 플래너 비교에는 영향이 없다.
