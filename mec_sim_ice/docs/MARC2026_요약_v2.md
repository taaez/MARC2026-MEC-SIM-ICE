## 1. 대회 구조 개요

- 로봇: 4륜 섀시 + 6축 로봇팔(Robotiq 2F-140 그리퍼)
- **Stage 1**: CCTV 영상 기반 VLA grounding — 자연어 명령을 듣고 대상 물체/사람의 좌표를 추정해 제출 (로봇 이동 없음, 순수 인식 문제)
- **Stage 2**: grounding + 실제 로봇 주행 + 물건 집기(pick) + 지정 장소로 배달(place)
  - Stage 1과 Stage 2는 **독립된 별개 단계**임. Stage 1의 카메라 선택 결과가 Stage 2로 넘어가는 게 아님.
  - Stage 2의 이동 목표는 grounding이 아니라 `on_stage2_reveal`이 주는 `hint_center`(대략 위치)에서 나옴 — grounding이 틀려도 수거는 계속 진행 가능.
- 통신: 전부 ROS 2 기반, `marc_sdk`(Python)로 감싸서 사용 권장. `marc_sdk`는 pip 패키지가 아니라 스타터킷 루트의 소스 폴더(경로만 PYTHONPATH에 잡으면 바로 import).

## 4. Stage 1 상세

### 처리 순서 (명령 해석이 먼저, 탐지가 나중)
```
MISSION_COMMAND 수신 (voice_command, round, total_rounds, time_limit)
    ↓
① 자연어 명령 해석 먼저
    → target_type (뭘 찾을지)
    → landmark (기준 사물, 있는 경우)
    → relation (공간관계, 있는 경우)
    → situation (사람 문제인 경우)
    ↓
② 해석 결과 바탕으로 CCTV 영상들에서 실제 탐지
    → list_cctv()로 카메라 목록 확보
    → 각 후보 카메라 get_cctv_image()로 영상 확보
    → target/landmark 함께 보이는 카메라 확정 (camera_id)
    → 픽셀 → world 좌표 변환
    ↓
③ GroundingResult 구성 → submit_grounding() 제출
```

### 명령 구조 2가지 유형 (추정 — 정확한 예문은 문서에 없음, 플랫폼 실행해서 확인 필요)
1. **분실물/관계형 문제**: "OO 옆/근처의 XX" 형태 → target_type + landmark + relation
2. **사람/SAR 문제**: 사람 상황 판단 → target_type="person" + situation

### relation 값 8종
```
near(근처), beside(옆), behind(뒤), front(앞), left(왼쪽), right(오른쪽), on(위-접촉), above(위-공중)
```

### situation 값 4종
```
accident, emergency, abnormal, normal
```

### GroundingResult 필드
```json
{
  "camera_id": "...",
  "interpretation": {
    "target_type": "...",
    "landmark": "...",
    "relation": "...",
    "situation": "..."
  },
  "grounding": {
    "anchor_coord": [x, y, z],
    "target_coord": [x, y, z]
  }
}
```

### 좌표 변환 참고
- CCTV extrinsic: `/tf_static` (world → camera_id), optical 규약(+Z 전방, +Y 아래)
- CCTV intrinsic: `get_cctv_info(camera_id)` (K 행렬)
- 지면 높이: `get_cctv_ground_height(camera_id)` — 픽셀→world 역투영 시 `z = ground_height` 평면 가정 (카메라마다 다름, 도로·잔디 단차 약 10cm 있으므로 배경 전체를 하나의 평면으로 가정하면 안 됨)

### 채점 기준 (Stage 1)
- 카메라 선택 정확도
- 객체·상황 해석 정확도
- 랜드마크·공간관계 정확도
- anchor/target 좌표 정확도 (부분점수)
- 라운드별 평균 = Stage 1 점수
- **정정 이력(2026.R02)**: 기준 랜드마크 정답 좌표를 "문항이 지정한 카메라 안"에서 찾도록 수정됨(과거엔 동일 이름 랜드마크가 다른 카메라에도 있으면 엉뚱한 좌표가 정답으로 잡히는 버그 있었음) → 최신 스타터킷으로 `git pull` 권장.

## 7. 라이다가 필요한 이유 (Stage 2용, Stage 1만 할 땐 필수 아님)

- CCTV(환경 카메라)는 Stage 1의 "인식" 용도
- 라이다는 로봇 몸체에 탑재된 센서로, Stage 2에서 실제 주행 시 근접 장애물 회피용
- 점유지도(`get_occupancy_map()`)는 정적 도로 정보만 담음(사람·물체 없음) → 실시간 장애물 감지는 라이다 담당
- 장애물이 정적이므로(사람 이동 없음) 표준 ROS2 navigation(전역계획+라이다 지역회피)으로 충분

## 8. 디텍션 모델 관련

- **대회가 지정한 모델 없음** — 자유 선택
- **런타임 인터넷 완전 차단** — 가중치·의존성은 빌드 시점에 도커 이미지에 baking 필수
- 탐지 모델은 전체 클래스를 커버해야 함 (라운드마다 target/landmark가 다름), 런타임에 이번 라운드 무관 객체는 무시 가능

### 2026년 기준 모델 옵션 비교
| 모델 | 특징 |
|---|---|
| YOLO11/YOLOv8 (Ultralytics) | 가장 무난, 학습·배포 쉬움, 문서·커뮤니티 풍부, 단 AGPL-3.0 라이선스 |
| RF-DETR | 2026년 최고 정확도로 꼽힘, COCO 60mAP 최초 돌파, Apache 2.0 |
| Grounding DINO / YOLO-World | 텍스트 프롬프트로 바로 탐지(재학습 불필요), auto-labeling에도 유용, 이 대회처럼 "명령→대상 특정" 구조와 궁합 좋음 |

→ 실전 추천: 처음엔 YOLO11로 빠르게 파이프라인 완성 → 정확도 개선 필요하면 RF-DETR 실험, 또는 Grounding DINO로 auto-labeling해서 YOLO 학습 데이터 보강하는 하이브리드도 고려 가능

## 9. 데이터셋 생성기 → YOLO 학습 파이프라인

### 데이터셋 생성기 (시뮬레이션 플랫폼에서 자동 생성)
```
cd simulation-platform
bash marc.sh dataset-gen
# 또는: docker compose --profile dataset-gen up
```
- 옵션: `ENV_MARC_SCENARIO`, `HEADLESS=true`, `TRAINER_AUTO_SCENES=100` (한 번에 최대 200장면)
- 결과물: `trainer_output/<시나리오>/scene_<번호>/<카메라>.json` + `.png` + `_overlay.png`(라벨 확인용)
- JSON 구조: `detections`(class, bbox[x_min,y_min,x_max,y_max], occlusion) + `camera`(intrinsic/extrinsic)
- **주의(2026.R03 패치)**: 캔·티슈처럼 눕혀 배치하는 물체, 자전거·킥보드·쓰레기통처럼 넘어뜨려 배치하는 물체의 bbox 좌표가 과거엔 실제보다 위쪽으로 잘못 기록됐었음(사람·벤치·차량 등 고정 대상은 영향 없었음). **패치 이후 이미지를 다시 생성했는지 반드시 확인.**

### JSON → YOLO 포맷 변환 (자동화 스크립트로 1회성 작업)
```python
def to_yolo(bbox, img_w, img_h, class_id):
    x_min, y_min, x_max, y_max = bbox
    x_c = (x_min + x_max) / 2 / img_w
    y_c = (y_min + y_max) / 2 / img_h
    w = (x_max - x_min) / img_w
    h = (y_max - y_min) / img_h
    return f"{class_id} {x_c:.6f} {y_c:.6f} {w:.6f} {h:.6f}"
```
→ 학습(개발 단계)에서만 필요, 실전 추론 시점엔 변환 불필요 (이미 학습된 가중치로 바로 예측)

### YOLO 학습
```python
from ultralytics import YOLO
model = YOLO("yolo11n.pt")
model.train(data="data.yaml", epochs=100, imgsz=1280)  # CCTV 해상도 1280x720 기준
```

### 실제 파이프라인 연결
```python
# mock_agent_vla.py 자리에 실제 구현
class RealVLAGrounding:
    def __init__(self, weights_path="weights/best.pt"):
        self.model = YOLO(weights_path)
    def process(self, voice_command, camera_ids=None) -> GroundingResult:
        target_type, landmark, relation = self._parse_command(voice_command)  # 명령 해석 먼저
        for cam_id in camera_ids:
            img = self._to_numpy(client.get_cctv_image(cam_id))
            results = self.model(img)
            det = self._find_target(results, target_type, landmark)
            if det:
                coords = self._pixel_to_world(det, cam_id)
                return GroundingResult(camera_id=cam_id, target_type=target_type,
                    anchor_coord=coords["anchor"], target_coord=coords["target"],
                    landmark=landmark, relation=relation)
        return GroundingResult(camera_id="", target_type=target_type,
                                anchor_coord=[0,0,0], target_coord=[0,0,0])
```

## 10. 제출 방법 (마감일 필수 3가지)

1. 리포지토리 루트 `docker-compose.yml`로 `docker compose up` 한 줄로 빌드~실행 완결 (다른 스크립트 개입 없음, 새 위치에 clone해서 확인 필수)
2. Private 리포지토리 `master`에 push + 제출 커밋에 태그(`qualifier`) 별도 push
   ```
   git tag -a qualifier -m "MARC 2026 qualifier submission"
   git push origin qualifier
   ```
3. `marc-challenge-office` 계정을 collaborator로 추가

### 환경변수
- `MARC_TEAM_ID`, `MARC_TOKEN`을 docker-compose.yml `:-` 뒤 기본값에 직접 하드코딩 (주최측은 env export 없이 실행)
- 토큰은 절대 공개 리포지토리에 노출 금지

### 도커 이미지에 모델 포함
- 가중치(`best.pt`)와 `ultralytics` 등 의존성을 빌드 시점에 이미지에 baking 필수
- 인터넷 끊고 `docker compose up` 정상 동작하는지 반드시 확인

### 평가 방식
- 주최측은 팀 리포지토리 clone → `docker compose up` 한 줄만 실행 (다른 조치 없음)
- 팀마다 내부 구현/언어/모델은 자유, Docker로 실행 환경을 통째로 캡슐화해서 표준화
- 팀별 순차 채점 (예선 채점 하드웨어: i7-12700K, RTX PRO 5000 48GB, RAM 125GB)

### 본선 진출 시
- 예선과 동일 절차, 태그만 `finals`로 변경

## 11. 트러블슈팅 자주 나오는 것 (신규 반영)

| 증상 | 원인/해결 |
|---|---|
| 뷰포트 검정 화면, 첫 실행 시 멈춘 듯 보임 | 정상 — 씬 로딩에 수 분 소요, 강제종료 금지 |
| WSL2에서 카메라 토픽/화면 안 나옴 | WSL2 미지원. 네이티브 Ubuntu 22.04 필요 |
| ROS2 Humble ↔ Isaac Sim Python 충돌 | 셸 분리 (참가자 코드는 Humble/3.10 셸, 플랫폼은 자체 셸) |
| GPU 인식 실패(`Failed to initialize NVML`) | NVIDIA Container Runtime/드라이버 확인, `--gpus all` 지정 확인 |
| 기동 직후 RTX 렌더러 Segfault | 590+ 베타 드라이버가 원인일 확률 높음 → production 580.x로 교체 + 셰이더 캐시 삭제 |
| `unknown or invalid runtime name: nvidia` | `sudo nvidia-ctk runtime configure --runtime=docker` 후 재시작 |
| DDS 통신 안 됨 | 동일 `ROS_DOMAIN_ID`·동일 LAN 확인, RMW는 Fast DDS 기본값 유지(Cyclone DDS 등으로 바꾸면 안 됨) |
| `marc-base:...: pull access denied` | base 이미지는 로컬 빌드 대상 — `marc.sh setup` 먼저 실행 |
| 성능 느림/VRAM 부족 | 해상도↓, 동시 구독 CCTV 스트림 수↓, 무거운 추론은 별도 하드웨어에서 |

## 12. 아직 확인 안 된 부분

- 실제 `voice_command` 예문 (시뮬레이션 플랫폼 직접 실행해서 로그로 확인 필요 — 문서에 정확한 문장 예시는 공개돼 있지 않음)
- 실제 채점에 쓰이는 시나리오/배경(비공개, 연습용 배경과 다를 수 있음 — 하드코딩 금지 명시됨)
- 정확한 채점 임계값·가중치 (공식 문서가 "큰 틀만 안내, 비공개"라고 명시)
